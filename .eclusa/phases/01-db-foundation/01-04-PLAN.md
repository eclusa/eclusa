**test_full_trace_chain**:
1. Seed (in order): actor → intent → cascade → stage → work_session → artifact
   - Each entity must link to the prior via FK
   - artifact must have: `intent_id`, `cascade_id`, `stage_id`, `session_id` all set

7. Assert `result['stage_id'] == stage_id`

**test_cycle_guard_terminates** (per PITFALLS.md Pitfall 2):
1. Seed actor → intent → cascade
2. Create two stages with a cycle: stage_A.depends_on = [stage_B_id], stage_B.depends_on = [stage_A_id]
   - Insert stage_A first with empty depends_on, then stage_B with depends_on=[stage_A_id], then update stage_A to depends_on=[stage_B_id] via direct SQL (this bypasses the trigger since it's not ledger_entry)
   - Actually: insert both stages, then seed an artifact linked to stage_A
3. Execute trace_chain.sql with that artifact's UUID
4. Assert query returns (not hangs) — the test itself enforces this via pytest timeout or just running to completion
5. Assert `is_cycle` detection worked: result row must not be None but is returned without error

Use `@pytest.mark.parametrize` to run once per SQL file:
```python
import pathlib, glob, pytest
METRIC_FILES = sorted(pathlib.Path("db/queries/metrics").glob("*.sql"))

@pytest.mark.parametrize("sql_file", METRIC_FILES, ids=[f.stem for f in METRIC_FILES])
async def test_metric_is_computable(conn, sql_file, seeded_metric_data):
    sql = sql_file.read_text()
    # Execute with 30-day lookback interval
    result = await conn.fetchrow(sql, "30 days")
    # The metric is computable if it executes without error
    # NULL return is acceptable only if there truly is no data — but we seeded data
    # so we assert the query completes (no error) and the first column is not None
    assert result is not None, f"{sql_file.name} returned no rows"
```

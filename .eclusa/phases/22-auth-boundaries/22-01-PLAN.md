Add two plain routes directly on the FastAPI `app` instance inside `create_app()`, after the `_shutdown` handler and before the middleware:

```python
@app.get("/healthz")
async def healthz() -> dict:
    """DB pool liveness check. Returns 200 + pool stats or 503 on failure. AUTH-04."""
    pool = app.state.pool
    if pool is None:
        from fastapi import Response
        return Response(
            content='{"status":"unavailable","detail":"pool not initialised"}',
            status_code=503,
            media_type="application/json",
        )
    try:
        async with pool.acquire() as conn:
            await conn.fetchval("SELECT 1")
        return {
            "status": "ok",
            "pool_size": pool.get_size(),
            "pool_free": pool.get_idle_size(),
        }
    except Exception as exc:
        from fastapi import Response
        import json
        return Response(
            content=json.dumps({"status": "unavailable", "detail": str(exc)}),
            status_code=503,
            media_type="application/json",
        )

@app.get("/readyz")
async def readyz() -> dict:
    """Readiness check — confirms DB pool responds. Returns 200 or 503. AUTH-04."""
    pool = app.state.pool
    if pool is None:
        from fastapi import Response
        return Response(
            content='{"status":"not_ready","detail":"pool not initialised"}',
            status_code=503,
            media_type="application/json",
        )
    try:
        async with pool.acquire() as conn:
            await conn.fetchval("SELECT 1")
        return {"status": "ready"}
    except Exception as exc:
        from fastapi import Response
        import json
        return Response(
            content=json.dumps({"status": "not_ready", "detail": str(exc)}),
            status_code=503,
            media_type="application/json",
        )
```

Note: import `Response` at the top of `app.py` — `from fastapi.responses import Response` — rather than inline.

   ```python
   async with pool.acquire() as conn:

           SELECT i.created_by
           FROM work_session ws
   ```

   Close code 4008 is used per the AUTH-02 specification. Note: RFC 6455 defines 4000-4999 as application-defined codes — 4008 is valid.

**adapters/web/api/chat.py** — decouple DB connection from LLM stream in `build_stream()`:

The current `build_stream()` holds a single `pool.acquire()` context across the entire `refine_agent.run_stream()` call. Fix: split into two separate connection acquisitions.

Replace the body of `build_stream()` (the inner async generator defined inside the `if body.mode == "build":` block) with:

```python
async def build_stream():
    # Phase 1: stream LLM response — no DB connection held during model call
    all_messages = []
    async with refine_agent.run_stream(
        user_prompt,
        message_history=history if history else [],
        deps=RefineContext(conn=None, actor_id=actor_id, intent_id=intent_id),
    ) as result:
        async for chunk in result.stream_text(delta=True):
            yield _stream_chunk("0", chunk)
        all_messages = result.all_messages()

    # Phase 2: short-lived DB write after stream completes
    history_json = serialize_history(all_messages)
    async with pool.acquire() as conn:
        await conn.execute(
            "UPDATE work_session SET message_history = $1::jsonb WHERE id = $2::uuid",
            history_json, str(session_id),
        )

    yield _stream_chunk("d", {"finishReason": "stop", "session_id": str(session_id)})
```

Important: `RefineContext` receives `conn=None` during the LLM stream. Check `harness/refine_agent.py` to verify whether `RefineContext.conn` is used during streaming (tool calls). If refine agent tools require a DB connection during streaming, a different pattern is needed — use a dedicated short-lived connection per tool call inside each tool implementation instead of holding one across the generator. In that case, pass `pool` to `RefineContext` instead of `conn`, and have each tool acquire/release its own connection. Document which approach was used in the SUMMARY.

The `event_stream()` function for non-build mode already acquires connections correctly (short-lived inside the generator after stream completes at line 234) — no change needed there.

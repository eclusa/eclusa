  <action>
Create ui/e2e/14-metrics-e2e.spec.ts with a Playwright test that:

1. **Data seeding via docker exec psql** (in test.beforeAll or test.beforeEach):
   Use `exec('docker exec ...')` pattern from Phase 9 Playwright tests. Build a single SQL script that inserts all required test data. Execute via:
   ```
   docker exec -i eclusa-db-1 psql -U eclusa -d eclusa -c "..."
   ```
   Alternatively, use the `child_process.execSync` to run the SQL. The SQL script seeds:

   a. **Actor:** INSERT INTO actor (id, type, identity, permissions) with a fixed test UUID
   b. **Intents:** 3 intents created by the test actor
   c. **Cascades:** 3 cascades (active state) linked to intents
   d. **Stages:** 6 stages (3 gate + 3 narrowing) across the cascades
   e. **Ledger entries for gates:**
      - 2x gate_surfaced (for 2 gate stages, timestamps = NOW() - interval '10 minutes')
      - 2x gate_resolved (for same 2 stages, timestamps = NOW() - interval '5 minutes')
        One with human_choice != system_recommendation, one with human_choice == system_recommendation
      - 2x gate_auto_resolved (for 2 other stages)
   f. **Ledger entries for cascades:**
      - 2x cascade_state_changed with content = {"new_state": "completed"}
      - 1x cascade_reopened (for one of the completed cascades)
      - 1x cascade_migration (for one cascade, after its gate_resolved timestamp)
   g. **Fan-out rows:**
      - 3 fan_out rows with completed_at set:
        2 with verdict='converged', 1 with verdict='diverged'
      - The diverged fan_out must have stage_id matching a gate_resolved entry
      - convergence JSONB with passes array and majority_verdict for minority_accuracy:
        {"majority_verdict": "approve", "passes": [{"model": "model-A", "verdict": "approve"}, {"model": "model-B", "verdict": "approve"}, {"model": "model-C", "verdict": "reject"}]}

   Use fixed UUIDs (v4 format, hardcoded strings) prefixed with a recognizable pattern like `00000013-...` for easy identification and cleanup.

   **IMPORTANT:** All timestamps must be within the last 30 days (the API lookback window). Use `NOW() - interval 'N minutes'` syntax.

2. **Authentication:** Use the existing `getAuthToken` helper from `./helpers/auth` to get a JWT token and set it in localStorage before navigating.

3. **Test: `test('metrics dashboard renders 8 cards with real values')`:**
   - Authenticate (set token in localStorage via addInitScript)
   - Navigate to `/metrics`
   - Wait for network idle (the useCalibrationMetrics hook fetches data)
   - Assert the heading "Metrics Dashboard" is visible
   - For EACH of the 8 metric titles, assert:
     a. The title text is visible on the page
     b. The empty state text "Requires 10+ resolved gates to compute." is NOT visible within that card's container
     c. The card contains a visible chart element or numeric display (indicating real data rendered)

   The 8 titles to check (from MetricsPage.tsx METRIC_DEFINITIONS):
   - "Gate Necessity Rate"
   - "Absorption Rate"
   - "Resolution Latency"
   - "Decision Durability"
   - "Cascade Rework Rate"
   - "Model Convergence Rate"
   - "Minority Model Accuracy"
   - "Fan-out Necessity Rate"

   **Assertion strategy:** For each metric title, locate the card container, then check that it does NOT contain the empty state message. The EmptyStateGuard renders "Requires 10+ resolved gates to compute." when value is null. So the test asserts this text appears 0 times across all 8 cards. If any metric returns null, the empty state text would appear in that card.

   Concretely:
   ```typescript
   // No empty state messages should be visible (all 8 metrics have data)
   const emptyStates = page.getByText('Requires 10+ resolved gates to compute.')
   await expect(emptyStates).toHaveCount(0)
   ```

   Also verify at least one card shows a Recharts SVG element (proving the chart rendered with real data, not just the card shell):
   ```typescript
   // At least one Recharts SVG should be present
   const charts = page.locator('.recharts-wrapper')
   await expect(charts.first()).toBeVisible()
   ```

4. **Cleanup** (in test.afterAll):
   Run cleanup SQL via docker exec psql that deletes all seeded data in FK order:
   - Disable ledger immutability trigger
   - DELETE FROM fan_out WHERE id IN (fixed UUIDs)
   - DELETE FROM ledger_entry WHERE cascade_id IN (fixed UUIDs)
   - DELETE FROM stage WHERE cascade_id IN (fixed UUIDs)
   - DELETE FROM cascade WHERE id IN (fixed UUIDs)
   - DELETE FROM intent WHERE id IN (fixed UUIDs)
   - DELETE FROM actor WHERE id = fixed UUID
   - Re-enable ledger immutability trigger

5. **Handle minority_accuracy specifically:** The minority_accuracy SQL query returns ROWS (GROUP BY model), not a single scalar. The API's _numeric_value extracts the first numeric column from fetchrow (first row). If the query returns 0 rows, it returns None. The seeded data must ensure at least 1 row: a gate_resolved where human_choice matches a minority pass verdict in the linked fan_out. The fan_out row's stage_id must match the gate_resolved row's stage_id.

6. **File structure:**
   - Import { test, expect, Page } from '@playwright/test'
   - Import { getAuthToken } from './helpers/auth'
   - Import { execSync } from 'child_process'
   - Use execSync for docker exec psql commands
   - Wrap seeding SQL in a function for readability
   - Test timeout: increase to 60s (seeding + page load + API response)

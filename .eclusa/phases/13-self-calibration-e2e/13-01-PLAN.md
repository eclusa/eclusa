Create tests/e2e/test_metrics_e2e.py with a comprehensive E2E test that:

1. **Seeding helper** (async function, not fixture -- called in test body for explicit control):
   - Create a test actor (type='system', permissions for resolve_gates + view_costs)
   - Create 3 intents + 3 cascades (active state)
   - For each cascade, create 2 stages (one gate, one narrowing)

2. **Seed data to satisfy ALL 8 metric SQL queries:**

   a. **gate_necessity (CAL-01):** Insert ledger entries:
      - `gate_surfaced` for stage X (with stage_id set)
      - `gate_resolved` for same stage X with content JSONB containing:
        `{"human_choice": "approve", "system_recommendation": "reject"}`
        (human != system so gate_necessity_rate > 0)
      - Also insert a second pair where human_choice == system_recommendation
        (so rate is 0.5, not 1.0 -- proves it's computing a ratio)

   b. **orchestrator_absorption (CAL-02):** Insert:
      - 2x `gate_surfaced` entries (from step a)
      - 2x `gate_auto_resolved` entries (for different stages)
      (absorption_rate = 2/(2+2) = 0.5)

   c. **resolution_latency (CAL-03):** The gate_surfaced and gate_resolved pairs from (a)
      already have timestamps. Ensure there is a time gap between surfaced.timestamp and
      resolved.timestamp (use explicit timestamps: surfaced = NOW() - interval '5 minutes',
      resolved = NOW() - interval '2 minutes', so latency ~180 seconds).

   d. **decision_durability (CAL-04):** The gate_resolved entries from (a) exist.
      For ONE of the resolved gates, insert a `cascade_migration` ledger entry with
      a later timestamp in the same cascade. This makes rework_rate = 0.5 (1 of 2 had rework).

   e. **cascade_rework (CAL-05):** Insert `cascade_state_changed` entries with
      content `{"new_state": "completed"}` for 2 cascades. For one cascade, also insert
      a `cascade_reopened` entry with a later timestamp. Rework rate = 0.5.

   f. **model_convergence (CAL-06):** Insert 3 fan_out rows directly into the fan_out table:
      - 2 with verdict='converged', completed_at set
      - 1 with verdict='diverged', completed_at set
      Convergence rate = 2/3 ≈ 0.667

   g. **minority_accuracy (CAL-07):** This is the hardest metric. Needs:
      - A fan_out row with stage_id matching a gate_resolved entry
      - fan_out.convergence JSONB must contain a `passes` array with objects having `model` and `verdict` keys
      - fan_out.convergence must have a `majority_verdict` key
      - gate_resolved.content->>'human_choice' must match a pass verdict that differs from majority_verdict
      Seed: fan_out with convergence = {"majority_verdict": "approve", "passes": [{"model": "model-A", "verdict": "approve"}, {"model": "model-B", "verdict": "approve"}, {"model": "model-C", "verdict": "reject"}]}
      And gate_resolved with content = {"human_choice": "reject", "system_recommendation": "approve"}
      This means the human picked the minority verdict (model-C's "reject")

   h. **fanout_necessity (CAL-08):** The 3 fan_out rows from (f) include 1 diverged.
      Necessity rate = 1/3 ≈ 0.333

3. **Test function:** `test_all_metrics_return_non_null`

**CRITICAL: Embedding strategy.** The embedding pipeline calls an external API (OPENAI_API_KEY). For E2E tests, DO NOT call the real embedding API. Instead, generate deterministic fake 1024-dim embeddings using a hash-based approach (e.g., hash the entity name, use it to seed a numpy-free random generator, produce 1024 floats). This keeps tests fast, deterministic, and free of API key dependencies. Insert entities directly via SQL with the fake embeddings -- do not use embed_schema_ir().

**Test: test_openapi_parse_to_schema_ir**
1. Read `tests/fixtures/sample.openapi.yaml` (already exists -- has User entity with id, name fields + listUsers operation).
2. Call `parse_openapi(text)` and assert: `len(ir.entities) >= 1`, entity named "User" exists, `len(ir.operations) >= 1`, operation named "listUsers" exists, `ir.source_format == "openapi"`.

**Test: test_openapi_entities_ingested_and_searchable (KG-E2E-01 core)**
1. Create a richer OpenAPI spec inline (at least 5 entities: User, Order, Product, Payment, Inventory) with descriptions and multiple operations. This ensures meaningful search differentiation.
2. Parse with `parse_openapi()`.
3. For each IREntity, generate a deterministic fake 1024-dim embedding vector. Use `hashlib.sha256(name.encode()).digest()` to seed, then expand to 1024 floats in [-1, 1] range. Normalize to unit length for cosine similarity to work correctly.
4. INSERT each entity directly into the entity table with the fake embedding:
   ```sql
   INSERT INTO entity (id, name, type, summary, embedding, created_at, updated_at)
   VALUES (gen_random_uuid(), $1, $2, $3, $4::vector, NOW(), NOW())
   ```
5. Call `hybrid_search("User", fake_embedding_for_user_query, conn, limit=10)`.
6. Assert: results is not empty, first result has name containing "User", first result has `rrf_score > 0`, first result has `cosine_score > 0`.
7. Verify BM25 signal: at least one result should have `bm25_score > 0` (the BM25 index on entity.name should match "User").
8. **Cleanup:** DELETE all inserted entities at end of test (they have no FK dependents).

**Test: test_fact_invalidation_and_as_of (KG-E2E-02 core)**
1. Create two entities (EntityA, EntityB) with fake embeddings, insert into entity table.
2. Create an episode via `INSERT INTO episode` (source='e2e-test', raw_data='{}', reference_ts=now).
3. Create a first fact between EntityA and EntityB with predicate "owns" and a fake embedding vector. Use `create_fact_with_invalidation()`. Record `fact_1_id` and `t1 = datetime.now(UTC)`.
4. Sleep 10ms (ensure timestamp difference). Record `t_between`.
5. Create a contradicting fact between same entities with predicate "leases" and an embedding that is very similar to the first (cosine > 0.90 to trigger invalidation). To guarantee this, use the SAME embedding vector as fact 1 (cosine = 1.0, definitely > INVALIDATION_THRESHOLD of 0.90). Record `fact_2_id` and `t2 = datetime.now(UTC)`.
6. Assert: `SELECT t_invalid FROM fact WHERE id = fact_1_id` -- t_invalid IS NOT NULL (old fact invalidated).
7. Assert: `SELECT t_invalid FROM fact WHERE id = fact_2_id` -- t_invalid IS NULL (new fact is current).
8. AS OF query BEFORE contradiction (at t_between):
   ```sql
   SELECT id FROM fact WHERE source_entity = $1 AND target_entity = $2
     AND t_created <= $3 AND (t_invalid IS NULL OR t_invalid > $3)
   ```
   Assert: returns fact_1_id only.
9. AS OF query AFTER contradiction (at t2 + 1 second):
   Same query with later timestamp. Assert: returns fact_2_id only.
10. **Cleanup:** DELETE facts, entities, episode.

  **Test 1: "sessions page has three-column submenu layout" (UI-E2E-01)**
  - First, create a chat session so there is at least one work_session in the DB. Send a message via the chat page: navigate to /chat, fill the input, click send, wait for assistant response. This ensures a session exists with a title derived from the intent.
  - Navigate to `/sessions`.
  - Wait for networkidle.
  - Assert the Sidebar is visible: `page.getByText('Chat')` is visible (nav column exists).
  - Assert the sessions submenu is visible: `page.locator('[data-testid="sessions-submenu"]')` is visible.
  - Assert at least one session item exists: `page.locator('[data-testid="session-item"]').first()` is visible.
  - Assert the main content area exists (the transcript section or empty state is rendered).
  - This proves the three-column layout: nav sidebar | sessions submenu | main content.

  **Test 2: "session status is colored dot, no badges or cost pill" (UI-E2E-02)**
  - (Continues from a state where sessions exist -- either use the same test or create a session first.)
  - Navigate to `/sessions`.
  - Locate a session item: `page.locator('[data-testid="session-item"]').first()`.
  - Assert a status dot exists inside it: `sessionItem.locator('[data-testid="status-dot"]')` is visible.
  - Assert the status dot has a `data-status` attribute with a valid value (running, completed, failed, etc.).
  - Assert NO text badge exists for status: the session item should NOT contain a Badge-like element with text matching "running", "completed", or "failed" as standalone badge text. Use: `expect(sessionItem.locator('text=/^(running|completed|failed)$/i')).toHaveCount(0)` -- but be careful not to match inside other elements. A simpler approach: assert no element with `border-blue-800/50` class pattern (the old Badge styling) exists.
  - Assert NO cost pill: the session item should NOT contain text matching a USD pattern like `/\d+\.\d+ USD/`.

  **Test 3: "sessions display generated titles not UUIDs" (UI-E2E-03)**
  - Navigate to `/sessions`.
  - Locate the first session item's title: `page.locator('[data-testid="session-title"]').first()`.
  - Get the title text content.
  - Assert the title does NOT match a UUID pattern: `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`.
  - Assert the title is not empty and has length > 0.
  - Assert the title text content is human-readable (not a UUID). Since the session was created via chat with a specific message, the title should contain recognizable text from that message.

  **Test 4: "clicking a session loads its transcript" (functional verification)**
  - Navigate to `/sessions`.
  - Click the first session item.
  - Wait for the URL to include `/sessions/` followed by a UUID.
  - Assert the transcript area shows content (either messages or "No transcript messages yet").

  Set `test.setTimeout(90000)` for the first test (creates a chat session). Others can use 60000.

  Use `test.describe('Sessions UI Polish -- Phase 14', () => { ... })` to group tests.

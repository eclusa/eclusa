# Phase 7.1.1: Chat Interface — Intent Creation via Agent Session

**Gathered:** 2026-04-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a chat interface to the back office where operators create work by talking to an agent. The conversation creates an intent → cascade, runs as a pydantic-ai work session, streams in real-time. This is the missing front door — without it, no user-facing flow exists.

Stack: assistant-ui + Vercel AI SDK (ai v6) + pydantic-ai VercelAIAdapter on FastAPI backend.

</domain>

<decisions>
## Implementation Decisions

### Backend
- **D-01:** POST /api/chat endpoint using pydantic-ai VercelAIAdapter — emits Vercel AI Data Stream Protocol (SSE)
- **D-02:** On first message: create intent + cascade + work session in DB, then stream agent response
- **D-03:** On subsequent messages: continue the existing work session, stream response
- **D-04:** Model selection via request header or query param — operator chooses model before starting
- **D-05:** Install pydantic-ai[ui] extra if needed for VercelAIAdapter

### Frontend
- **D-06:** Install assistant-ui, @assistant-ui/react, ai (Vercel AI SDK v6)
- **D-07:** ExternalStoreRuntime + Zustand store — we own message state, assistant-ui observes
- **D-08:** ChatPanel component in sidebar or as a new /chat route
- **D-09:** Tool call display built into assistant-ui — show when agent calls tools
- **D-10:** Model selector dropdown (configurable list of available models)
- **D-11:** Cost chip per message (tokens_in/tokens_out from work session cost JSONB)

### Intent → Cascade bridge
- **D-12:** First message in chat creates: intent (source='web'), cascade (from SCC template or generic), work session linked to cascade stage
- **D-13:** Subsequent messages continue the same work session
- **D-14:** When session completes, cascade progresses to next stage

### Integration
- **D-15:** Chat sessions visible in the existing Sessions page (transcript viewer)
- **D-16:** Cascades created via chat appear in the Dashboard
- **D-17:** Gates surfaced during chat appear in the Gates view

</decisions>

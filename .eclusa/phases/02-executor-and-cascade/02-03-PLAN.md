Create executor/cascade.py with four async functions:

**claim_ready_stages(conn: asyncpg.Connection, limit: int = 10) -> list[dict]**
- Must use SKIP LOCKED inside explicit conn.transaction() — Pitfall 1
- Exact query from RESEARCH.md Pattern 1 and RESEARCH.md Readiness Query section:
  SELECT s.id, s.type, s.cascade_id, s.depends_on, s.input, s.retry_count
  FROM stage s JOIN cascade c ON s.cascade_id = c.id
  WHERE s.state = 'pending' AND c.state IN ('active', 'evergreen')
  AND NOT EXISTS (SELECT 1 FROM stage dep WHERE dep.id = ANY(s.depends_on) AND dep.state NOT IN ('resolved', 'skipped'))
  FOR UPDATE OF s SKIP LOCKED LIMIT $1
- Inside same transaction: UPDATE stage SET state = 'active' WHERE id = ANY($1) for claimed rows
- Returns list of dicts (from asyncpg Record objects)

**retry_stage(conn: asyncpg.Connection, stage_id: str, actor_id: str) -> None**
- Per D-19: max retry count is 3. If stage.retry_count >= 3, raise MaxRetriesExceeded (define as a module-level exception class in cascade.py — do not use a generic ValueError so callers can distinguish retry exhaustion from other errors).
- Inside explicit conn.transaction():
  - SELECT stage.retry_count FOR UPDATE to lock the row
  - If retry_count >= 3: raise MaxRetriesExceeded(f"Stage {stage_id} has exhausted 3 retries") — no DB write
  - UPDATE stage SET retry_count = retry_count + 1, state = 'pending' WHERE id = $stage_id
  - INSERT ledger_entry with type='stage_state_changed', content={'old_state': 'active', 'new_state': 'pending', 'reason': 'retry', 'retry_count': new_count}, schema_version='0002'

**apply_pending_migration(conn: asyncpg.Connection, system_actor_id: str) -> bool**
- Check for active stages before applying: if any stage in cascade is 'active', return False (D-15)
- Read one pending proposal: SELECT ... FROM cascade_migration_proposal WHERE status = 'pending' ORDER BY created_at ASC LIMIT 1 FOR UPDATE SKIP LOCKED
- Snapshot old cascade.shape
- Validate: all stage IDs in new_shape depends_on arrays must exist in stage table for that cascade. Raise ValueError if not (Pitfall 6).
- UPDATE cascade SET shape = new_shape WHERE id = cascade_id
- INSERT ledger_entry with type='cascade_migration', content={old_shape, new_shape, reason, applied_at}, schema_version='0002'
- UPDATE cascade_migration_proposal SET status='applied', applied_at=NOW() WHERE id=proposal_id
- All in one transaction. Returns True if applied.

**check_cascade_completion(conn: asyncpg.Connection, cascade_id: str, actor_id: str) -> None**
- Query: does ANY stage in this cascade have state NOT IN ('resolved', 'skipped', 'failed')? If yes, return (not complete yet).
- If all terminal: check if any stage is 'failed'.
  - If failed and failure_policy='fail_cascade': UPDATE cascade SET state='failed' + UPDATE pending stages SET state='skipped' + INSERT ledger_entry cascade_state_changed failed
  - If failed and failure_policy='skip': UPDATE remaining pending/blocked stages to 'skipped'. UPDATE cascade SET state='completed'.
  - If no failures: UPDATE cascade SET state='completed', completed_at=NOW() + INSERT ledger_entry cascade_state_changed completed
- All writes in one transaction with ledger entries.

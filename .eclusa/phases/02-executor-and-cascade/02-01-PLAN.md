upgrade() must execute exactly these DDL statements in order:

1. ALTER TABLE cascade ADD COLUMN failure_policy TEXT NOT NULL DEFAULT 'fail_cascade'
   -- Stores D-17 policy: 'retry' | 'skip' | 'fail_cascade'. DEFAULT is conservative per D-18.

2. ALTER TABLE cascade ADD COLUMN parent_stage_id UUID REFERENCES stage(id) ON DELETE SET NULL
   -- D-11: sub-cascades link back to the stage that spawned them. NULLABLE (root cascades have no parent).

3. ALTER TABLE stage ADD COLUMN retry_count INTEGER NOT NULL DEFAULT 0
   -- D-19: tracks how many times this stage has been retried. Incremented by executor on each retry ledger entry.

4. CREATE TABLE cascade_migration_proposal (
       id UUID PRIMARY KEY,
       cascade_id UUID NOT NULL REFERENCES cascade(id),
       proposed_by UUID NOT NULL REFERENCES actor(id),
       new_shape JSONB NOT NULL,
       reason TEXT,
       status TEXT NOT NULL DEFAULT 'pending',
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       applied_at TIMESTAMPTZ
   )
   -- Pitfall 5 resolution: mutable proposal lifecycle without touching append-only ledger.
   -- status values: 'pending' | 'applied' | 'rejected'

5. CREATE INDEX idx_migration_proposal_cascade_id ON cascade_migration_proposal(cascade_id)
6. CREATE INDEX idx_migration_proposal_status ON cascade_migration_proposal(status)

downgrade() must reverse all of the above in reverse order:
  DROP INDEX idx_migration_proposal_status
  DROP INDEX idx_migration_proposal_cascade_id
  DROP TABLE cascade_migration_proposal
  ALTER TABLE stage DROP COLUMN retry_count
  ALTER TABLE cascade DROP COLUMN parent_stage_id
  ALTER TABLE cascade DROP COLUMN failure_policy

Use op.execute() for all DDL (consistent with 0001 pattern). Do NOT use op.add_column() — use raw ALTER TABLE statements.

**Test function: `test_simple_blog_workspace_agent`**

Follow the exact pattern from test_24_dogfood_scc_journey.py for DB setup and pipeline execution:

1. **Setup**: Create intent with raw text "Build a simple blog with Flask. The blog should have a home page listing all posts and a page to create new posts. Store posts in memory (no database needed). Each post has a title and body."

2. **Create SCC cascade**: Either use `create_scc_cascade` from executor/scc.py or manually insert cascade + stages. Include all 7 stages (refine/fanout can be pre-resolved with a scope doc to save LLM calls and test time). The key stages to test are derive, generate, ship.

3. **Pre-resolve early stages**: To focus the test on derive/generate/ship and save LLM calls:
   - Pre-resolve refine with a scope doc output
   - Pre-resolve fanout (auto-resolve)
   - Pre-resolve match with empty matched_sources
   - Pre-resolve cohere with a simple verdict
   - Pre-resolve formalize with a Haskell source stub (or skip output)
   - Leave derive, generate, ship as pending

4. **Run pipeline**: Use `single_poll_cycle` in a loop (with timeout) to dispatch derive, generate, ship stages. Use `asyncio.timeout(350)` as the outer timeout (matching Phase 24 pattern).

5. **Verify derive stage**:
   - Stage reaches 'resolved' state
   - Workspace directory `workspaces/{cascade_id}/` exists
   - At least one .py test file exists in the workspace
   - The test file contains `def test_` or `class Test`

6. **Verify generate stage**:
   - Stage reaches 'resolved' state
   - Workspace contains implementation files (e.g., app.py or main.py)
   - Workspace contains a Python file with `flask` or `Flask` in it

7. **Verify ship stage**:
   - Stage reaches 'resolved' state
   - Stage output contains `workspace_dir`
   - Stage output contains `commit_hash`
   - A git repository exists in the workspace with at least one commit

8. **Verify workspace contents**:
   - `read_workspace_files(workspace_dir)` returns files
   - At least one file contains Flask-related code

9. **Docker/HTTP verification** (best-effort — Docker may not be available in test env):
   - If Docker is available and stage output has `deployment_url`, attempt HTTP GET
   - If HTTP GET returns 200 with HTML content, assert success
   - If Docker is not available, log a warning but don't fail the test (Docker availability is environment-dependent)

10. **Cleanup**: Remove workspace directory after test. Remove Docker container if created.

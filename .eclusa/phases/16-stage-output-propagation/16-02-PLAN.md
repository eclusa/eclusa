<objective>
Add GET /api/cascades/{id}/stages endpoint that returns per-stage status for UI consumption, including the human-readable SCC stage name extracted from stage.input.

Purpose: The existing GET /api/cascades/{id} endpoint returns stages but only with id/type/state/created_at. Phase 18 (Cascade Pipeline UI) needs to render the 7 SCC stages by name with their status. This endpoint provides that, extracting the scc_stage key from the JSONB input column and including resolved_at timestamps.

Output: New route in adapters/web/api/cascades.py.
</objective>

SQL query for this endpoint:
```sql
SELECT
  s.id,
  s.type,
  s.state,
  s.input->>'scc_stage' AS scc_stage,
  s.created_at,
  s.resolved_at,
  s.depends_on
FROM stage s
WHERE s.cascade_id = $1::uuid
ORDER BY s.created_at ASC, s.id ASC
```

If `cascade_id` not found (no rows returned), raise `HTTPException(status_code=404, detail="Cascade not found")`.

Map each row to `StageDetail`, resolving `display_name` from `_SCC_DISPLAY_NAMES.get(scc_stage)`.

The `depends_on` column is a UUID array from asyncpg — it returns as `list[UUID]` directly. Handle the case where it may be `None` or empty list by defaulting to `[]`.

Do not modify the existing `StageStatus` model or `get_cascade` endpoint — they are used by other parts of the codebase.

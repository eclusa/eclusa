<objective>
Implement executor-level upstream output injection so every SCC stage receives the accumulated context from all prior resolved stages in the pipeline.

Purpose: Currently stages 3-7 (Match, Cohere, Formalize, Derive, Generate) receive only their static creation-time input keys (e.g., `{"scc_stage": "match"}`). The `query_text`, `matched_sources`, `formalize_output`, `test_suite`, and related keys are never present because upstream outputs don't exist at cascade creation time. The result: match queries with empty text, cohere analyzes nothing, derive generates from nothing. Propagation fixes this by having the executor inject upstream outputs into `stage.input` before dispatch.

Output: `executor/propagation.py` with `inject_upstream_context`, loop.py wired to call it, and scc_handlers.py cleaned up to read from injected stage.input.
</objective>

```python
"""executor/propagation.py — upstream output injection before stage dispatch (PROP-01, PROP-02).

inject_upstream_context(conn, stage):
  1. Walk the full ancestor graph via recursive CTE on depends_on[]
  2. Collect output JSONB from all resolved ancestors (NULL outputs skipped)
  3. Apply key-mapping rules to translate output keys into the keys handlers expect
  4. Merge all mapped keys into stage.input (existing keys preserved, ancestors fill gaps)
  5. UPDATE stage SET input = merged_input WHERE id = stage_id
  6. Return the updated stage dict (with input mutated in place for the caller's copy)
"""
```

**Key mapping rules** (translate ancestor output keys into what downstream handlers read):

| Ancestor scc_stage | Output key | Injected as |
|--------------------|------------|-------------|
| refine | scope_doc | query_text (for match to search against) |
| match | (list — the output itself) | matched_sources |
| cohere | (dict — the verdict) | cohere_output |
| formalize | haskell_source | haskell_source; full output dict as formalize_output |
| derive | test_suite OR derived_tests | test_suite AND derived_tests |

Use a recursive CTE to collect all ancestor IDs in one DB roundtrip:

```sql
WITH RECURSIVE ancestors AS (
  SELECT id, depends_on, input, output
  FROM stage
  WHERE id = ANY($1::uuid[])   -- direct parents of the dispatching stage
  UNION ALL
  SELECT s.id, s.depends_on, s.input, s.output
  FROM stage s
  JOIN ancestors a ON s.id = ANY(a.depends_on)
)
SELECT id, input, output FROM ancestors WHERE output IS NOT NULL
```

After collecting ancestor rows, apply key mapping, merge into current stage.input (shallow merge — don't overwrite keys that already exist from stage creation), then:

```sql
UPDATE stage SET input = $1::jsonb WHERE id = $2::uuid
```

Also mutate the in-memory `stage["input"]` dict so the caller's copy is up-to-date (dispatch_stage receives the same dict object).

**Important:** `dispatch_scc_fanout` manually queries `refine_stage_id` from `stage.input` — DO NOT change this behavior. Fanout is a special case that looks up ONE specific upstream stage by stored ID. The injection adds to `stage.input` but doesn't remove `refine_stage_id`, so fanout continues to work unchanged.
